## 工程裁定与代价（Rulings）

1. 沿用当前隔离云工作区与 `preview/xumu-demo` 分支：不新建 worktree；代价是只使用云工作区这一层隔离。
2. 技能辅助脚本及链接测试参考不可读取时，手工维护等价任务、测试与裁定记录，执行已读取的 TDD 规则；代价是没有辅助脚本自动化。
3. 任务 1 提前扩充桌面状态兼容类型以保持编译，演示持久化白名单保持独立；代价是新 UI 之前共享视图类型已经扩大。
4. 中断恢复在任务 2 随真实尝试事务及测试实现，不在任务 1 放空实现；代价是任务 1 单独只交付存储与迁移。
5. 每次尝试持久化确认快照及适配器版本，增加内部批次查询/完成逻辑，暂停时释放未开始的预留；代价是记录略大、事务路径更多，已覆盖测试。
6. 内部动作有独立超时预算；超时后先保存不确定结果，关闭对应 context 并等待原动作结束；代价是若损坏适配器在 context 关闭后永不结束，队列保持阻塞，不能冒险与其并发写入。当前生产适配器禁用。
7. 增加只读批次列表并在页面进入时恢复暂停入口；代价是额外 DTO 查询，已完成历史限最近 20 个批次。
8. 官方访问受阻时交付禁用适配器与原生验收步骤，不制作猜测的选择器；代价是真实身份与发布仍不可用。
9. 用真实 Linux 打包程序扩充旧库升级与修订重启验收，不为已经实现的行为制造人工 RED；代价是此包装层验收不替代 Windows 原生运行，核心行为的失败测试已在对应任务先行完成。
10. Windows 工作流使用 `npm ci --ignore-scripts` 后显式准备 Electron；代价是依赖新增安装脚本时需明确评估，当前依赖无变化且 Linux 实际加载验证通过。

11. 以持久事件 ID 区分重发意图之前已知的提交历史与之后的新提交，预留事务再次检查，核对页也列出阻塞；代价是额外的任务事件查询，无需修改 schema 或 DTO。
12. GitHub API 不可访问时推送新版本标签请求 Windows 原生 CI，保留 Actions 入口；代价是一次 CI 运行，当前无法确认其结果，不宣称安装包已生成。

13. 实际 Electron 测试等待主窗口创建后再运行主进程夹具，避免 Inspector 在原生 SQLite 模块加载途中重入；代价是测试必须等待应用初始化，不用固定睡眠或放宽业务断言。

## 最终独立审阅与单次修复

一次完整独立审阅覆盖基准 `0547f80` 至 `8e53204`、设计、计划与全部 Review Focus。发现 Critical 0、Important 4、Minor 0；没有延后的小问题。四项 Important 均在一次集中修复中处理，没有再次开启独立审阅循环。

| 发现 | 修复及失败 → 通过回归 |
| --- | --- |
| 旧失败任务可绕过同账号/视频的新版提交历史 | 核对与预留事务检查兄弟任务历史；明确重发意图只覆盖其创建前的已知提交。测试普通旧草稿和旧重发草稿在新任务发布/受限后被阻止，并保留正常新重发路径 |
| 最后一次视频 hash 期间切换身份仍可提交 | 两处写入都先校验视频，再立即核实实时身份/context/能力；延迟 hash 并换号，上传准备与提交次数均为 0 |
| 暂停后当前任务完成但界面仍显示执行中 | 批次暂停后，只要仍有执行中任务就继续刷新；分别验证官方回执与不确定结果会在原页面更新并显示核对入口 |
| 最终清单缺少具体视频 | 显示视频文件名与完整 SHA-256；两个同名视频、相同账号和文案仍可清楚区分 |

完整回归一度出现原生模块夹具启动重入与暂停测试超时；测试启动器改为等待实际主窗口后才操作内部对象，再针对异常重复验证并运行全套。新增 6 项实际 Electron 回归，全部先观察到预期失败，再修改实现；最终完整桌面、浏览器、重新打包后的验收均通过。截图从修复后的实际桌面重新生成。
