# 抖音多账号运营工作台：Windows 首版设计

日期：2026-10-17（Asia/Shanghai）

文档状态：用户已确认书面设计并认可已交付的界面效果演示；Windows 桌面实现进入实施计划阶段，真实站点能力尚未验证。

## 1. 已确认的目标与约束

用户需要在 Windows 上管理本人或公司自有的多个抖音账号，集中完成扫码登录、视频发布和评论、私信处理。用户目前没有抖音开放平台应用，希望在自己的电脑上扫码登录后使用软件。

已确认采用 Windows 桌面应用，使用独立浏览器配置管理账号会话。登录凭据不需要交给开发者，浏览器会话不上传到服务器。首版包含账号档案、素材库、发布队列、任务中心，以及经真实网页验证后启用的评论和私信操作。

自动刷视频、模拟真人养号、制造虚假互动不在范围内。该边界不影响自有账号的内容发布和正常客户沟通。

成功标准是用户能够安装应用、打开真实登录页面完成扫码、隔离不同账号、管理本地素材和任务，并在经过验证的网页功能中执行明确确认的发布和回复。展示样例数据、打开一个浏览器或单纯显示“已登录”不算真实接入成功。

## 2. 方案选择

| 方案 | 收益 | 限制 | 决定 |
| --- | --- | --- | --- |
| Windows 桌面应用与浏览器辅助操作 | 符合本机扫码需求；可以先验证已有网页能力 | 依赖网页实际功能和页面变化；需要 Windows 实机验收 | 首版采用 |
| 开放平台接口 | 接口边界明确，便于后续维护 | 当前无应用及接口权限；不同能力需分别核实 | 保留适配器边界，未来另行接入 |
| 纯网页素材与任务后台 | 本地业务功能容易验证 | 不能独自实现本机独立浏览器会话和实际站点操作 | 不作为主交付形式 |

扫码建立网页登录会话，不等同于获得开放平台接口权限。浏览器路线也不能在未验证前承诺自动发布、评论和私信都可用。

## 3. 运行方式与技术结构

首要交付目标为 Windows 11 x64 桌面安装包；Windows 10 x64 的兼容性单独记录，不在未测试时宣称支持。

采用 Electron、React、TypeScript 和 Vite。Electron 主进程负责文件对话框、数据库、浏览器进程和任务执行；React 渲染进程负责中文管理界面。通过受限 preload 接口通信，渲染进程不直接访问文件系统或浏览器会话。

使用 SQLite 持久化账号档案、素材、任务、草稿和结果。数据库驱动选择 better-sqlite3，安装与打包时针对 Electron ABI 构建；必须通过实际主进程的数据库读写检查，不能仅以 Node 单元测试替代。Windows 打包使用 electron-builder，并在 Windows 上验证原生依赖和安装后启动。

浏览器使用 Playwright Core 管理本机已安装的 Chrome 或 Edge，通过独立 persistent context 保留每个账号的配置。应用不启用反检测插件、不伪造设备特征。浏览器缺失时给出安装 Chrome 或 Edge 的指引，不静默下载未经验证的可执行文件。

本地模块划分：

| 模块 | 职责 | 对外约定 |
| --- | --- | --- |
| 账号服务 | 建档、分组、独立配置、登录观察 | 账号 ID、登录状态、能力状态 |
| 素材服务 | 文件导入、校验、标题与封面管理 | 素材 ID、文件位置、指纹及可用性 |
| 任务服务 | 创建、确认、调度、暂停与恢复 | 任务状态与结构化事件 |
| 站点适配器 | 登录观察、发布、消息读取与回复 | 显式能力报告和可核对的操作结果 |
| 消息服务 | 本地会话列表、筛选、草稿及处理状态 | 账号归属、远端消息标识及同步状态 |
| 本地存储 | 事务、迁移、错误恢复 | 不向界面暴露数据库或配置目录任意访问 |

站点适配器必须分别报告登录、发布、评论读取、评论回复、私信读取、私信回复的可用性，不使用一个全局“已接入”状态概括所有能力。

## 4. 界面与用户流程

界面使用中文侧栏导航：概览、账号、素材、发布任务、消息、设置。初次启动显示真实空状态，不自动创建虚构账号、任务或未读消息。

### 4.1 账号与扫码登录

1. 用户填写账号备注和分组，应用生成内部 UUID 及专用浏览器配置目录。
2. 点击“扫码登录”打开该配置对应的真实抖音登录或创作者页面，二维码由真实站点显示。
3. 用户自己完成扫码和站点要求的验证。应用不收集密码、短信码或聊天中传入的 Cookie。
4. 适配器只有在观察到可验证的账号身份信息时才标记“已登录”；仅页面打开或 URL 变化不够。
5. 无法可靠识别时显示“待确认”，允许用户在官方页面继续操作，但禁止据此自动执行任务。
6. 登录过期后暂停受影响的任务，保留草稿与素材，重新扫码后由用户决定恢复。

账号状态为“未登录、登录中、已登录、已过期、待确认”。同一账号配置只允许一个活动浏览器上下文，账号切换不得共享配置目录。若检测到相同远端账号重复绑定，提示用户处理，不静默合并不同本地记录。

### 4.2 素材管理

通过系统文件对话框批量导入视频，默认复制到应用管理的素材目录，记录原文件名、文件大小、SHA-256、导入时间及本地位置。文件复制先写临时文件，完成后再登记，失败不留下“可发布”的素材记录。

支持编辑标题、说明、标签、封面路径与本地备注。封面同样复制到应用目录。首版支持 MP4 与 MOV 的本地导入；具体站点是否接受该视频，在发布前由适配器按已验证规则检查。扩展名检查不等同于证明视频满足平台要求。

重复文件按内容指纹提示，不静默丢弃。删除素材前检查未完成任务引用，引用中的素材不得直接删除。文件损坏、丢失或不可读时标记不可用并阻止执行。

### 4.3 发布队列

用户选择素材、目标账号和发布信息，查看“素材—账号”明确映射后确认创建任务。一个素材发布至多个账号时产生独立任务，每个任务保存创建时的发布信息快照，后续修改素材不改变已确认任务。

首版任务由用户手动启动批次；不增加无人值守的定时发布。全局只执行一个站点操作任务，减少配置冲突并方便用户观察。运行中的平台操作结束后才进入下一个任务；未执行任务可以取消。

确认后流程为：检查素材与账号、打开目标页面、检查账号身份、选择视频、填写信息、执行已确认的发布、核对结果。每次远端写入前再次检查账号身份，防止账号错配。

只有获得可验证的发布结果，例如作品标识或官方页面明确确认，才标记成功。提交后连接中断、页面关闭或结果无法判断时进入“结果待核对”；不得自动重发。用户核对官方页面后记录结果，或在明确未发布时重新确认重试。

### 4.4 评论与私信

评论和私信分别验证，任何一项未完成真实站点验证时，界面显示具体未接通状态，并提供“打开官方页面”入口，不伪造消息同步或发送成功。

经过验证的读取能力可以将用户当前可访问的消息同步到本地，按账号、消息类型和本地处理状态筛选。同步范围以实际可观察的分页和消息边界为准，显示最近同步时间，不承诺无限历史或实时全量同步。

回复以单条选中消息为单位：用户编辑或选择已有草稿，明确看到目标账号、收件人和内容后点击发送。首版不包含批量私信、群发推广或无人审核的自动回复。只有远端确认成功才标记发送成功；结果不明确时先核对，不自动重发。

“已处理”是本地运营标记，与站点“已读”区分。暂不支持的附件、撤回和消息类型显示原始类型说明或官方页面入口，不假装已处理。

### 4.5 任务中心与恢复

展示任务账号、素材、状态、最近事件和可执行操作。状态流转为：

`草稿 → 待执行 → 执行中 → 成功 / 失败 / 结果待核对`

等待登录的任务单独显示“等待登录”；任务被取消后进入“已取消”。暂停批次只阻止后续任务启动，不强行撤销已提交的平台动作。

进程意外退出后，已记录远端写入开始但尚无确定结果的任务进入“结果待核对”；尚未写入远端的任务恢复为待执行。用户未重新启动批次前不自动发布。

## 5. 数据与文件约定

应用数据放在 Electron 的当前用户 userData 目录，不写入程序安装目录。子目录区分数据库、媒体、账号浏览器配置、临时文件及应用日志。

主要数据实体：

- Account：内部 ID、备注、分组、可验证远端身份、配置目录标识、登录状态、最近检查时间。
- Asset：内部 ID、内容指纹、受管相对路径、原始文件名、类型、大小、标题、说明与标签。
- PublishTask：ID、账号 ID、素材 ID、发布信息快照、状态、远端写入阶段、远端作品标识、最近错误与时间。
- TaskEvent：任务 ID、阶段、时间、脱敏错误类别和不含凭据的事件说明。
- Message：账号 ID、消息类型、远端会话与消息标识、对方显示信息、正文、远端时间、本地处理状态、同步时间。
- ReplyDraft：源消息 ID、文本、更新时间、发送状态与可核对的远端结果。
- CapabilityObservation：账号 ID、能力名称、可用性、观察时间及失败原因。

外键和事务保证任务不能引用不存在的账号或素材。需要迁移时先备份数据库，迁移失败保留原数据并阻止启动写入。

## 6. 会话、隐私与桌面边界

不把二维码、Cookie、浏览器配置、消息正文或凭据上传给开发者或远端服务。应用本身不增加遥测和云同步；浏览器仍需与用户正常使用的抖音服务通信。

浏览器配置目录包含敏感会话信息，留在当前 Windows 用户的数据目录；不提供导出 Cookie 或跨设备复制登录的功能，也不声称浏览器配置目录默认全部加密。若应用后续需要存储额外认证材料，使用 Windows 保护能力及 Electron safeStorage，不使用源码中的固定密钥。

渲染界面启用 contextIsolation，关闭 nodeIntegration，通过白名单 IPC 暴露具体操作，并在主进程校验参数、文件来源和账号归属。界面不接受任意 shell 命令、JavaScript 或浏览器脚本输入。外部网页不在拥有本地权限的应用渲染器中加载。

日志不记录消息正文、二维码内容、Cookie 或认证头。默认不自动截图；必要诊断截图由用户主动触发并提示包含个人信息的可能性。删除账号时先关闭浏览器上下文，明确区分删除本地档案与删除本机登录配置；软件不执行远端账号注销。

## 7. 失败处理与能力边界

浏览器缺失、账号登录过期、素材不可读、网页结构变化和网络错误均产生具体提示，保留用户输入和任务记录。验证码及站点要求的身份验证交给用户在真实页面完成，不尝试绕过。

若网页端某项功能不能稳定访问或未对该账号开放，停止该项自动操作，保留素材、草稿和打开官方页面的人工流程。未验证功能不能以“模拟成功”替代。测试适配器和夹具仅用于自动化测试，不作为正式版默认数据源。

当前云环境曾访问官方开发文档失败，返回代理 403；因此本文不据此断言评论或私信 API 的具体权限。正式站点选择器、登录证据和消息范围需要在实际可访问的官方页面中核实，不编造私有接口或选择器。

## 8. 实施顺序与验收

采用一个桌面应用，按以下顺序交付；每一步区分已运行、已验证和需要用户设备验证的结果：

1. 桌面骨架与本地业务：账号档案、真实空状态、素材导入、持久化任务、失败恢复和中文界面。
2. 浏览器会话：打开独立配置、用户扫码、真实身份判断、过期处理、账号切换。先验证一个账号，再验证两个账号隔离。
3. 视频发布：单素材单账号闭环；确认结果与不确定结果处理通过后，再验证批量任务和恢复。
4. 消息管理：评论与私信分别验证读取、目标识别、草稿和人工发送；仅启用已经实测的能力。
5. Windows 打包与验收：安装、启动、浏览器发现、原生数据库、非 ASCII 路径、含空格路径、重启恢复及卸载后数据处理。

本地核心测试必须覆盖任务状态流转、错误账号阻断、重复发布保护、崩溃恢复、账号配置隔离、文件导入失败、数据库持久化及消息目标归属。界面测试至少验证账号创建、素材导入、任务映射和未接通能力状态。

真实站点验收使用用户自己的账号与测试素材；任何发布或回复都由用户在软件里明确确认。真实站点验证不要求用户把账号凭据放入聊天或测试仓库。离线测试通过不能代替该验收。

当前开发环境为 Linux，能够验证 TypeScript、前端构建、核心逻辑、数据库迁移及可用的桌面测试；不能仅根据这些结果声称 Windows 安装包已通过实机验收。若无法访问真实站点或缺少用户本机扫码，明确记录未执行项目，并交付可复现的 Windows 验证步骤。

完成报告分别说明：本地工作台、账号登录、真实发布、评论、私信、Windows 安装包各自状态，不使用一个“全部完成”掩盖未验证能力。
