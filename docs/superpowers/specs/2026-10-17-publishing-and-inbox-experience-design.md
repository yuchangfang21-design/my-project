# 序幕：发布与消息管理的后续体验设计

日期：2026-10-17。状态：设计评审稿，尚未实现真实发布或消息接入。

## 1. 目标与现有基础

用户希望继续完成自有抖音账号的 Windows 运营软件设计。沿用已经确认的中文界面、独立浏览器账号配置、本机数据保存和人工确认方式；不重复选择技术路线。

0.2.0 已实现账号档案、独立浏览器启动、受管视频、本地任务及故障恢复。本稿补齐发布前核对、结果待核对、统一消息工作台三处体验，并细化实现时必须遵守的状态与账号归属约束。图中的账号、消息、数量和状态均为设计示例。

成功标准：用户在操作前能看清“哪个账号、哪条视频或消息、将执行什么”；操作后能区分确定结果、审核中和待核对。离线效果稿不表示已经取得平台能力。

## 2. 布局选择与设计语言

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 保留现有侧栏，列表与右侧核对区并排（采用） | 与当前软件一致；查看账号与任务时不丢失上下文 | 窄窗口需要将核对区改为抽屉 |
| 全屏分步向导 | 初次使用容易理解 | 多账号来回核对步骤较多 |
| 全表格加快捷操作 | 高密度处理较快 | 容易忽略账号与结果说明 |

继续使用暖白背景、橄榄绿主操作、淡紫与杏色分类。绿色表示已确认或可继续，琥珀色表示等待核对，红色只用于明确错误或不可继续；状态同时使用文字，不依赖颜色判断。

桌面主要布局适配 1440 × 1000 和 1280 × 900。宽度不足 1200 时将右侧核对区改为可打开的抽屉，保留其顶部账号信息；最窄按现有桌面最小窗口 960 × 700 检查。所有确认弹层支持键盘操作、焦点约束和明确关闭入口。触发期间禁用重复提交。

## 3. 发布前核对

入口保留“发布任务”。创建本地任务与启动远端发布是两个独立动作。

1. 选择素材和目标账号，编辑作品标题、说明及标签；页面显示每一条“素材—账号”映射。每个账号可以单独修改文案。
2. 保存为本地任务。原素材后续修改不覆盖已保存的任务信息；编辑任务会生成新修订版本。
3. 点击“核对并启动”，展示本次选中的任务、素材、各目标账号的已观察身份和完整文案。备注名与站点身份分开显示。
4. 未核实身份、素材不可用或发布能力未验证的任务显示具体阻塞原因；这些任务不纳入启动确认。被排除的条数和原因必须可见，不能悄悄跳过。
5. 最终按钮写明“确认发布 N 条”，而不是模糊的“确定”。确认覆盖固定任务 ID 与修订版本；任务修订、实际视频指纹或目标身份变化后，本次确认失效，要求重新核对。原素材的标题编辑不改变已有任务快照。长文案可以展开或滚动查看，不能用省略号替代确认内容。
6. 用户主动启动后串行执行。每次写入前重新检查实时身份与已确认目标一致，不能把历史登录记录作为本次依据。

副本 SHA-256、可读性及标题长度在执行前再次检查。平台视频格式、封面和标题限制只能使用真实页面验证过的规则；本地 MP4/MOV 识别不能替代平台校验。

尚未验证的能力始终显示“发布接入待验证”，原 0.2.0 不会因为本稿或示例截图启用发布按钮。设计稿中可点击状态代表未来通过验证后的预期体验。

## 4. 执行中、暂停与取消

主列表显示任务、目标账号、最近步骤、结果和操作。右侧显示当前任务的素材缩略图、作品信息和事件时间线。

全局同一时间只执行一项站点操作，包括发布、消息同步和回复发送。等待期间显示队列原因；同一账号的页面操作不能互相导航覆盖。登录窗口可供用户核对，执行中修改到其他身份会使本任务停止或进入待核对。

“暂停后续任务”只阻止下一项启动，不宣称能够撤回正在提交的作品。尚未开始的任务可取消。上传和填表阶段可请求停止；已经上传的站点草稿不保证被自动删除。写入意图已记录后的任务不再显示“取消发布”，改为“停止后续任务”和“核对结果”。

账号需要扫码或站点验证时暂停批次，保留本地信息；用户在真实页面完成后重新核对并手动继续，不自动恢复执行。

## 5. 结果与恢复

| 用户可见状态 | 判定与下一步 |
| --- | --- |
| 待执行 | 尚未启动，或能证明未进入远端提交阶段；可编辑、取消或核对启动 |
| 等待登录 | 需要扫码或验证；不能自动提交 |
| 执行中 | 显示检查账号、上传、填写、提交或核对结果等实际阶段 |
| 已提交 · 审核中 | 已取得可核实的作品标识和官方提交确认，尚无可见发布结果 |
| 已发布 | 已观察到该作品的官方发布状态；显示作品入口 |
| 发布受限 / 未通过审核 | 显示观察到的原因和官方页面入口，不自动换号重发 |
| 失败 | 能明确确定没有成功提交；再次尝试仍由用户主动确认 |
| 结果待核对 | 提交可能已经发生，但没有确定结果；禁止自动重试 |
| 已取消 | 在允许取消的阶段停止；保留本地任务事件 |

数据库在点击真实提交前写入“准备提交”的持久事件。进程在记录与点击之间中断也按不确定结果处理，宁可人工核对一次，不冒重复发布的风险。只有 HTTP 成功、页面变化、上传完成或短暂提示，都不足以单独判定发布成功。

重启不自动执行队列。恢复时，存在提交标记但没有确定回执的任务进入“结果待核对”；其他中断任务回到可重新检查的待执行状态。新旧任务状态迁移保留 0.2.0 的待执行、已取消和标题快照，迁移前备份数据库。

待核对任务的右侧提供三个清晰入口：

- **打开官方作品页**：在该任务的账号配置中查看，不能跨账号打开来证明结果。
- **重新检查结果**：只读取当前任务的作品记录，不执行提交。没有唯一对应证据时继续待核对，不把同标题作品当作同一条任务。
- **记录人工核对**：可记录“已找到作品”或“确认未发布”。人工记录与自动确认分开标注，不能手工填写一个链接就冒充自动核实成功；重新发布仍需再次检查身份和用户确认。

出现结果不确定时暂停整个批次。用户可以排除待核对项后手动恢复其余任务；批次摘要一直保留待核对数量。已经成功或待核对的任务不能通过普通“重试”再次提交。同一账号、同一视频出现已提交历史时显示记录，只有用户明确创建新发布意图并再次确认，才允许再次发布。

## 6. 统一消息工作台

按现有消息页扩展三列：账号筛选、消息列表、会话与回复区。账号很多时账号筛选可收起；会话顶部始终保留“使用哪个账号回复谁”。

账号、消息类型（评论 / 私信）、本地待处理状态可以组合筛选。未接通的类型单独显示原因；空列表明确区分“没有匹配消息”“尚未同步”“同步失败”，不能把读取失败显示为没有消息。

能力分别记录为评论读取、评论回复、私信读取、私信回复。仅已验证的读取能力允许同步，界面显示每个账号与类型的最近同步时间、读取条数和范围。同步失败保留上次数据并标记不是最新；不承诺全量历史或实时同步。

每条消息保存账号 ID、远端会话标识及远端消息标识；去重键包含账号与消息类型。切换账号后不能复用上一账号的会话目标。评论需要保留作品及评论归属，不能只靠昵称定位。昵称不是唯一收件人标识。

回复区提供编辑草稿与保存。停止输入后 500 毫秒保存草稿，切换消息前等待当前草稿保存；保存失败则保留输入、提示原因并停留在当前消息。草稿按账号与源消息独立保存，只有数据库确认后显示“已保存在本机”。发送前展示固定的发送账号、收件人、来源消息与完整文本；修改任一项会使发送确认失效。

首版逐条人工发送，单次确认只覆盖一条回复。发送前再核实账号和目标，记录发送意图，只有观察到唯一对应的远端结果才显示已发送。超时或崩溃后进入“发送结果待核对”，保留草稿并阻止自动重发。“标记已处理”仅影响本地运营状态，与站点已读和发送成功独立。

未验证回复能力时允许保存草稿和打开官方页面，发送保持不可用。附件、撤回等尚不支持的类型给出说明。消息正文按文本渲染，不执行内容中的 HTML；站外链接不在有本地权限的窗口中直接加载。

消息页效果稿属于完整产品的体验设计；消息持久化与接入会另有独立实施计划，不混入发布执行器的第一轮落地。

## 7. 模块与数据衔接

| 设计单元 | 责任与边界 |
| --- | --- |
| 发布编辑与核对界面 | 编辑本地任务、展示映射和确认范围；不能直接调用站点脚本 |
| 发布服务 | 保存修订快照、检查确认版本、创建执行意图、解释结果 |
| 站点操作协调器 | 串行调度发布、同步、回复；管理暂停与账号页面占用 |
| 站点适配器 | 观察实时身份和单项能力，执行受限动作并返回证据；不暴露任意脚本接口 |
| 本地事件与恢复 | 提交前持久记录意图，保存确认回执与错误，决定重启后的待核对状态 |
| 消息与草稿服务 | 维护账号归属、同步游标、本地处理标记和逐条发送意图 |

发布信息包含任务 ID、修订版本、账号 ID、目标远端身份、素材 ID 与指纹、标题说明标签快照、用户确认记录、执行尝试 ID、提交阶段、作品标识、提交结果与平台审核状态。提交结果与审核状态分开存储。

能力证据关联账号、当前浏览器上下文、能力类型、验证版本和观察时间。上下文关闭、身份变化或网页结构失配即失效；持久化的旧观察不能单独启用远端写入。

主进程仍只暴露具名业务操作，校验来源与参数；不接受渲染进程传来的浏览器脚本、绝对文件路径或原始 SQL。日志只保存阶段、错误类别、时间和非敏感标识，不记录消息正文、扫码内容或会话凭据。诊断截图仍需由用户主动触发。

## 8. 实施拆分与验收标准

| 阶段 | 可审阅交付 | 启用条件 |
| --- | --- | --- |
| A：发布准备与恢复 | 单账号发布闭环、确认版本、持久事件及恢复，再扩展多账号串行批次 | 有真实账号身份与发布页面的验证依据，先用测试素材确认 |
| B：评论工作台 | 评论读取、归属、草稿与逐条回复，分别启用能力 | 独立验证评论读取与回复；不能拿发布成功代替 |
| C：私信工作台 | 私信会话、同步、草稿与逐条回复 | 独立验证私信读取与回复及账号可用范围 |

下一份实施计划只细化阶段 A。B、C 各自保留独立设计与实施验收，避免一轮同时改动全部站点能力。

验收需覆盖：素材恢复后可继续准备；账号错配阻止写入；连续点击只创建一次尝试；编辑后旧确认失效；全局任务串行；提交前后各故障点重启；无唯一证据时不标成功；待核对不自动重发；审核中不显示已发布；旧数据库迁移失败保留原始数据；消息去重与草稿隔离；同步失败不清空旧消息；回复不确定结果不重复发送；未接通能力无法发送。

离线验证只证明状态逻辑、归属和界面行为。Windows 安装、真实扫码、单素材单账号发布、多账号隔离、评论、私信均需分别记录实机结果。当前云端站点访问受阻，不能编造页面选择器或把设计稿当作接入验收。

## 9. 效果稿与评审范围

本次请求交付设计与效果稿，不改动 0.2.0 的实际业务开关。评审重点是页面布局、核对内容、异常恢复和消息归属。设计确认后，再编写阶段 A 的可执行实施计划。
