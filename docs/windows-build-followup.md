## 0.4.1 素材修复与原生复测

第二次原生诊断 [39116873439](https://github.com/yuchangfang21-design/my-project/actions/runs/39116873439) 已失败，并给出可复现原因：Windows 临时路径含 `RUNNER~1`，普通文件与打开句柄的 inode 相同，文件读取、SHA-256、修改时间均正常，但父目录规范路径的拼写不同。旧代码把 `realpath(dirname) !== resolve(dirname)` 一概当成符号链接，因而拒绝正常源视频，也连带阻断素材修复、发布任务夹具和导入取消测试。

0.4.1 将源路径先 `resolve`，再逐级 `lstat` 父目录，拒绝符号链接、Windows junction 和非目录；短路径与大小写别名可以使用。打开文件后继续核对普通文件、inode，并补充设备号一致性。复制、哈希、去重、临时文件及失败恢复逻辑保持原有门槛。回归增加 Windows 大小写别名导入和嵌套 junction 路径拒绝，Linux 覆盖目录符号链接祖先。

发布界面也在1000px本地复现了2项相同的模态遮挡。界面夹具现在显式指定宽屏 renderer viewport，所有1440/1280/960响应式切换也明确设置并断言 `innerWidth`，因此测试不依赖 Windows runner 显示器大小。仍实际启动 Electron；不使用强制点击，不取消焦点约束和退出保护。

一次独立只读审阅：Critical0、Important0、Minor1。唯一小问题是仅断言总数可能掩盖“别名误拒绝与junction误接受相互抵消”；已补充精确失败文件名和链接拒绝理由断言，没有延期问题。

相关22项实际Linux Electron测试通过；补强后的完整76项实际Linux Electron测试全部通过（约3.8分钟）。CI摘要增加独立 totals notice，避免GitHub每步骤错误注释数量限制掩盖实际失败总数；新增用例先失败，修复后8项全部通过。Windows工作流仍执行全部浏览器、Electron、打包后启动测试，最后才计算安装包SHA-256并上传产物；哈希同时写入公开构建注释便于核对。
