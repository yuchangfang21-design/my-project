# Windows 评论阶段 B 验收

本清单基于0.4.0评论本地核心，当前0.4.2检查版继续使用 `UnverifiedCommentsAdapter`，不能同步或发送真实评论。本地评论核心与实际抖音接入分别验收；私信属于阶段 C，尚未接通。

## 获取与安装

在[0.4.2成功构建](https://github.com/yuchangfang21-design/my-project/actions/runs/39129469306)的Artifacts中下载 `Xumu-Windows-x64` 实际产物。解压后校验 `SHA256SUMS.txt`，运行 `Xumu-0.4.2-win-x64.exe`。源码ZIP和HTML演示不是Windows软件安装包。0.4.2的“生成接入检查”用于后续联调，不能同步或发送评论，详见[官方接入跟进](official-site-integration-followup.md)。

使用测试副本，退出旧程序后备份整个本机工作区。不要上传工作区、浏览器 profiles、Cookie、二维码、真实评论、私信或素材至仓库。安装和卸载默认保留用户数据；不要使用真实工作区进行故障注入。

## 原生本地验收

- 首次打开没有示例账号或评论。消息中心明确显示读取和回复待验证、私信尚未接通。
- 从 0.3.0 / schema2 测试副本升级：核查发布回执、事件、标题与文案未变；数据库迁移至3，并产生一个迁移前备份。使用打包程序运行 `npm run test:packaged` 对应的完整测试；CI 使用实际 `win-unpacked/xumu-workspace.exe`。
- 对明确标记的本地测试评论编辑草稿：500ms停止输入后显示数据库确认的修订；清空、切换评论、账号、搜索、处理状态与页码、离开页面后再回来，内容独立且保留。
- 打字后立即通过窗口关闭按钮和应用退出分别退出，再启动核查最后文本。拒绝保存或修订冲突时窗口仍开，原输入仍在；解决问题后再次保存/退出。操作系统强制结束无法保证未入库的500ms输入。
- 重启含提交标记但无唯一回执的测试副本：结果仍待核对，不自动重新发送；有确定回执的状态和草稿仍保留。“标记已处理”只影响本地状态。
- 1440×1000、1280×900、960×700检查无整页横向溢出；小窗详情抽屉能用 Tab / Shift+Tab / Escape 操作，关闭后焦点回到来源按钮。
- 原生检查工作区、数据库、备份与 profiles 的 Windows 用户访问权限。Linux 的 POSIX mode 验证不代表 NTFS ACL 已通过。

## 官网能力门槛（当前未执行）

使用自己的 Windows 官方账号窗口，分别记录脱敏证据：

| 能力 | 启用前必须验证 |
| --- | --- |
| 当前身份 | 每次操作读到稳定远端账号标识，与绑定账号、当前 page/context 一致；扫码成功提示或历史 logged_in 不够 |
| 评论读取 | 每条记录包含真实作品、线程、评论和稳定作者标识；同昵称不同作者可区分；分页游标、重复页、范围终点和删除/不支持类型明确 |
| 评论回复 | 源评论及完整归属可以再次观察；准备填写与最终发送是独立控件；填写阶段不发送；改号、源文变化、删除或控件改版时立即停止 |
| 成功回执 | 唯一远端回复 ID，且账号、作品、线程、源评论、收件人全部匹配；提示气泡、HTTP成功或昵称相同不能作为成功 |
| 故障恢复 | 点击前后各中断点、断网、重复点击、窗口关闭、只读核对均不产生自动重发；人工“已找到/未找到”与官方结果单独显示 |

只有取得证据并先为真实解析写脱敏失败测试，才静态接入经过验证的适配器。读取与回复单独验收；发布功能通过不代表评论通过。不通过时保留禁用状态，不猜 DOM 选择器，不接受 renderer 传入身份、脚本或官方回执。每次真实测试回复仍由用户逐条核对确认，是否删除由用户决定。

当前云端没有用户的 Windows 官方会话；真实评论读取、回复发送和 Windows 安装验收均不能在此宣称完成。具体云端回归及交付状态见 [阶段 B 交付记录](comments-stage-b-delivery.md)。
