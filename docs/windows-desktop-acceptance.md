# 序幕 Windows 桌面基础版验收

## 当前能力

桌面基础版保存真实账号档案、导入并复制 MP4/MOV 文件、检测重复内容、建立本地任务和取消任务。各账号通过 Playwright 打开独立 Chrome/Edge 配置；扫码由官方页面提供。

抖音页面身份解析尚未完成实机验证，所以打开登录页面后保持“待确认”，不将二维码扫描或页面打开当作身份已核实。真实发布、评论和私信同步、回复发送尚未实现。

HTML 演示与桌面版数据相互独立。桌面版首次启动为空，不包含“山野咖啡”等示例账号，不显示虚构播放量。

## 生成 Windows 安装包

登录仓库所属 GitHub 账号，打开仓库的 Actions，选择 **Build Windows desktop**，点击 **Run workflow**，分支选择 `preview/xumu-demo`。

工作流会安装锁定依赖和官方 Electron，执行浏览器测试、实际 Electron 桌面测试，打包 Windows x64，再启动打包后的程序验证 SQLite 与重启。仅在步骤成功后上传 **Xumu-Windows-x64** 构建产物。

也可以由开发者主动推送 `desktop-build-*` 标签触发一次 Windows 构建；该标签只触发测试和仓库构建产物上传，不创建公开 Release。当前云端 GitHub API 请求被拒绝，推送 Git 成功不能代替 Actions 成功；需要在 Actions 页面查看实际结果。

若需要在 Windows 本机从源码构建，安装 Node.js 24、Chrome 或 Edge，在项目目录执行：

```powershell
npm ci --ignore-scripts
npm run desktop:prepare
npx playwright install chromium
npm test
npm run test:desktop
npm run desktop:dist -- --win --x64
npm run test:packaged
```

`better-sqlite3` 13 随经过 npm 完整性校验的依赖包提供 Node-API 预编译模块，已在实际 Electron 中验证加载，因此不需要重新下载 Electron 头文件或强制 ABI 重编译。Windows 加载仍由 Windows 测试单独验证。

安装包未配置开发者代码签名，程序文件属性可能保留 Electron 信息。本项目不提供关闭系统防护的操作指引。不要把“生成了 exe”当作 Windows 安装、启动或扫码验收已通过。

## 人工安装与真实扫码验收

1. 从实际成功的 Actions 运行中下载产物，或使用明确标注为未验证的候选包。核对随包提供的 SHA-256。
2. 以普通 Windows 用户安装和启动；首次显示空工作区，设置页显示桌面版本与 SQLite 本地数据。
3. 添加两个不同账号档案；分别点击扫码登录。两者应出现独立浏览器窗口；重复点击同一账号应复用对应窗口。
4. 在官方页面自己扫码、完成官方验证；不向聊天、开发者或 GitHub 提交密码、短信码、Cookie、二维码或浏览器配置。
5. 关闭账号一的浏览器，不应影响账号二；关闭桌面应用应关闭它所管理的浏览器。重新启动后账号档案仍存在；身份未核实前保持待确认。
6. 导入路径包含中文与空格的真实视频；移动原文件后，受管副本仍存在。同内容导入第二次应报告重复。
7. 创建“素材—账号”任务，修改素材标题后，原任务保留创建时的标题。取消任务后，关闭重开仍显示已取消。
8. 在设置中导出档案；JSON 不应包含视频原内容、绝对文件路径、Cookie 或浏览器会话。该文件不属于完整视频备份。
9. 检查网络不通、浏览器缺失、文件已移动或无读取权限时的提示；用户已输入的标题和账号信息不应被清空。
10. 卸载默认保留当前用户的应用数据；不要把卸载应用等同于远端账号注销。

应用默认使用 Electron 当前用户的 userData。可在启动时通过标准 `--user-data-dir=绝对路径` 指定独立的数据位置，供迁移或隔离验收使用；不要让两个实例同时使用同一账号配置。

相同数据目录重复启动会切回已有程序。启动时会校验受管视频：文件缺失或损坏后应显示重新导入提示，不能继续创建该素材的任务。重新导入相同原视频应报告“恢复”，保留原素材标题、分类和已有任务；正常退出应取消未完成导入并清理应用临时文件。
