## 1. 获取并检查 Windows 产物

1. 登录有仓库访问权限的 GitHub 账号，打开 [Build Windows desktop](https://github.com/yuchangfang21-design/my-project/actions/workflows/windows-build.yml)，选择对应 `desktop-build-0.3.0` 标签的运行。也可在 `preview/xumu-demo` 分支手动启动。
2. 确认前端、Electron、Windows NSIS、打包版测试全部成功后，下载 `Xumu-Windows-x64` 产物。源码 ZIP 和 HTML 演示不是安装程序。
3. 在 PowerShell 运行 `Get-FileHash .\Xumu-0.3.0-win-x64.exe -Algorithm SHA256`，与产物内 `SHA256SUMS.txt` 对照。当前没有开发者签名；文件属性、安装体验仍待 Windows 实测。
4. 以普通用户安装到带中文、空格的路径。启动后应是自己的空工作区；最小窗口 960 × 700，详情在窄窗口内以抽屉打开。
5. 创建两个账号档案、导入测试 MP4，分别保存标题、说明和标签；退出重开，应保留内容与修订。文件选择框只接受用户主动选取的素材。

## 2. 旧库、权限与恢复

先在自己的设备上备份完整应用数据目录，包括数据库及 WAL、media 和 profiles；不能只复制正在使用的 SQLite 主文件。默认数据目录由 Electron userData 决定，安装卸载保留数据。

- 用 0.2.0 工作区启动新版本，核对 pending/cancelled 任务、标题、事件、素材和账号数量；迁移应生成 `workspace-backup-*.sqlite`。备份是数据库一致性快照，不包含视频和浏览器配置。
- 备份目录无写入权限时应拒绝迁移；恢复权限后再启动。Windows ACL 失败场景需要实机单独验证；POSIX 权限测试不代表 Windows ACL 通过。
- 同一数据目录启动第二个进程，不得同时写入；第二个进程退出并聚焦原窗口。
- 删除受管视频副本后应显示缺失并阻止执行，用原视频重新导入恢复同一素材；原任务标题不能被素材编辑覆盖。
- 编辑保存后故意发出旧修订请求，应显示冲突并保留输入，只有主动重新载入才覆盖编辑区。
- 当前默认未验证适配器下，所有核对清单都应显示阻塞原因，确认发布按钮不可用；此项是本版本的预期行为。

## 3. 后续适配器开发的证据门槛

需要在自有 Windows 设备的官方登录窗口取得以下依据；无需向聊天或仓库上传密码、二维码、Cookie、浏览器配置或私人内容。

| 能力 | 所需真实证据 |
| --- | --- |
| 身份 | 当前页面稳定的远端账号标识、展示名、切换账号与退出时的变化 |
| 准备 | 实际上传和文案控件、页面版本、站点视频及文案限制；准备动作不能点击发布 |
| 提交 | 唯一提交控件及提交后可核实的作品标识、目标账号和官方回执 |
| 结果 | 同一作品的审核中、已发布、受限状态，以及实际官方作品 URL/入口 |
| 不确定结果 | 超时、页面改版、提示成功但无唯一作品 ID 时，能停止并保留待核对 |

把去除敏感内容的最小页面结构制作成夹具，先写失败测试，再实现适配器。必须经当前 context、实时身份与页面版本验证后才可启用。未取得上述证据之前继续保留禁用实现，不能编造 DOM 选择器。

## 4. 适配器完成后才执行的真实验收

以下各项当前均未执行。将来只能由用户在自己的设备上明确确认测试素材，实际内容是否保留或删除由用户决定。

1. 单账号、单条素材：核对完整文案、远端身份、目标映射，主动确认后提交。审核中显示“已提交 · 审核中”，只有同一作品的明确发布状态才显示“已发布”。
2. 两个自有账号：确认独立浏览器配置与不同远端标识，串行执行，每条提交前复核身份；切换到另一身份必须阻止提交。
3. 快速重复确认：同一清单只建立一个批次和一次尝试。编辑任务、修改视频字节、重开 context 后，旧确认必须失效。
4. 提交前中断：重启回到待执行，不自动执行。提交标记后断网或退出：重启进入结果待核对，整个批次暂停，不能自动重发。
5. 人工核对：记录找到作品不能冒充官方发布成功；记录未找到也不自动重发。需要新的核对与主动确认。
6. 离开发布页再返回，应仍显示运行批次与暂停入口；暂停只阻止后续任务，不表示撤回当前提交。真实适配器若超时，关闭对应 context 并等待操作结束后才能放行其他站点操作。
